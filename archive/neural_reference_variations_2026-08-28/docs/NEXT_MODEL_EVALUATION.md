# Выбор генеративной модели после AudioX

## Решение

Основной моделью снова является **Stable Audio Open 1.0**. Это единственная
проверенная архитектура проекта, которая уже дала естественные и практически
полезные вариации на `wood_creak`. Возврат не означает повтор глобального
strength sweep: проверяется новый masked Reference SDEdit с пошаговым
удержанием атаки reference trajectory.

## Закрытые маршруты

Глобальный Stable Audio Open Reference SDEdit, reference-preserving
residual/magnitude/phase методы, Stable Audio 3 Small-SFX и off-the-shelf
AudioX больше не являются основным направлением.

Stable Audio 3 проверен двумя принципиально разными способами:

- нативное audio-to-audio зашумление разрушало импульсный выстрел и давало
  широкополосный артефакт;
- локальное изменение SAME latent сохраняло событие, но три слепых candidate
  воспринимались как копии reference с металлическими артефактами.

Таким образом, рабочей области «то же событие, но новый естественный дубль» у
этого checkpoint не найдено. Дополнительный подбор углов, seed и noise level
остановлен.

## Отрицательный результат AudioX

AudioX был выбран не по размеру или популярности, а потому что официальный
checkpoint одновременно поддерживает:

- `audio_prompt` как cross-attention условие;
- `init_audio` с управляемым зашумлением latent;
- 44.1 kHz stereo;
- полный waveform generation, а не наложение второй формы волны на reference.

Это напрямую проверяет гипотезу диссертации: умеренно зашумлённое
представление reference проходит условный denoising и должно дать новый дубль
без потери события.

Важное ограничение: опубликованный production-oriented тест AudioX для SFX
использовал дополнительную адаптацию на ESC-50 в течение 4000 шагов. Поэтому
результат статьи нельзя приписывать публичному checkpoint заранее. Сначала
проверяется один off-the-shelf smoke; при неуспехе принимается решение о малой
адаптации, а не запускается бесконечный sweep параметров.

Источники:

- <https://github.com/ZeyueT/AudioX>
- <https://huggingface.co/HKUSTAudio/AudioX>
- <https://arxiv.org/abs/2607.09973>

Лицензия AudioX — CC BY-NC 4.0, а веса содержат watermark и разрешены только
для некоммерческого использования. Это допустимо для исследовательского
демонстратора, но не даёт права выпускать коммерческий инструмент на этих
весах.

## Результат инженерного аудита

Аудирован commit AudioX
`3bdfb7081636b9e62224039e37dadaa264dc781f` и публичный config
`HKUSTAudio/AudioX`:

- checkpoint: `5 957 258 603` байт;
- зарегистрированные параметры: `1 489 064 196`;
- DiT: `1 056 828 544` параметра;
- FP16-веса зарегистрированных модулей: `2.774 GiB`;
- CPU-сборка config: `7.41 GiB` RSS на текущей машине;
- модель работает с фиксированным окном `485100` samples, то есть 11 секунд;
- audio prompt подготавливается как 10-секундное условие.

Штатный Gradio-путь признан небезопасным для RTX 5070: он сначала создаёт и
загружает модель в FP32, держит все компоненты на одном device и удваивает
batch для CFG. Проект использует отдельный runner с memory-mapped checkpoint,
FP16, последовательным CFG и поочерёдным offload conditioner/DiT/decoder.

## Выполненный gate AudioX

1. Изолированное overlay-окружение создаётся внутри `artifacts/audiox_env` и
   наследует проверенный PyTorch 2.7.1+cu128.
2. Read-only preflight требует не менее 28/18 GiB total/free RAM, 16 GiB
   свободного диска и прежние 12000/10000 MiB total/free VRAM.
3. Checkpoint обязан иметь точный размер; неполная загрузка блокирует запуск.
4. Первый GPU-запуск — один seed, noise `0.10`, sequential CFG `3.0`, два
   denoising step. Это только проверка памяти и корректности тракта.
5. Smoke сохраняет reference, deterministic VAE-mean codec round-trip,
   11-секундный output и candidate, обрезанный до длины reference.
6. Успешный smoke с peak reserved VRAM не выше 8000 MiB открывает один
   50-шаговый full-test с теми же seed, noise и CFG.
7. До прослушивания codec round-trip и 50-шагового candidate запрещены серии
   seed и parameter sweeps.
8. Если codec уже меняет тембр неприемлемо или full-test разрушает событие,
   AudioX закрывается без denoising sweep. Если оба файла пригодны, следующий
   запуск — несколько seed при одном зафиксированном noise.

Gate завершён. Технически модель уложилась в память RTX 5070: двухшаговый smoke
и один 50-шаговый прогон достигли peak reserved `4784 MiB`, без OOM и без
лишнего громкого выстрела. Слуховой критерий не выполнен:

- codec round-trip испортил тембр;
- candidate воспринимается как тот же выстрел;
- полезного отличия нет;
- присутствуют артефакты.

По заранее заданному правилу дополнительные AudioX seed, noise и CFG не
проверяются. Runner и результаты сохраняются как воспроизводимая отрицательная
абляция.

## Следующая причинная гипотеза Stable Audio Open

Глобальное зашумление меняло микроструктуру атаки, где сосредоточена
идентичность выстрела. Masked Reference SDEdit разделяет роли:

1. первые `300 мс` удерживаются на forward-noised reference trajectory после
   каждого scheduler step;
2. следующие `140 мс` используют плавный cosine-переход;
3. остальная часть latent свободно денойзится по тому же prompt и seed;
4. весь результат один раз декодируется VAE, без waveform mixing.

Первый gate фиксирует strength `0.30`, seed `17`, четыре шага и одну пару. Если
тракт и память корректны, разрешается ровно одна 50-шаговая пара. Критерий
продолжения слуховой: сохранённая идентичность и естественность при слышимом
полезном изменении тела или хвоста и отсутствии второго выстрела.

## Резервные модели

Первый резерв — Catch-A-Waveform, который обучает single-example waveform GAN.
Риск: авторы обычно используют десятки секунд материала, а текущий выстрел
длится 1.71 секунды.

Второй резерв — SpecSinGAN: он сформулирован именно для one-shot SFX, но не
имеет официальной публичной реализации, а лучшие результаты статьи использовали
разделённые sound layers. Самостоятельная реализация допустима как отдельный
эксперимент, но не как быстрый следующий запуск.

- <https://github.com/galgreshler/Catch-A-Waveform>
- <https://arxiv.org/abs/2110.07311>
